# DocDiff 1.8 性能报告（测试版 1.8.0-beta.1）

测试机：云端 Linux，Intel Xeon 2.1 GHz × 2 核（比常见的笔记本慢）。所有样本都是 `scripts/make-review-fixtures.py`、`scripts/make-slow-pdf-fixtures.py` 生成的虚构文档。
对比方式：1.7.5 和 1.8 在同一台机器上**交替**运行，避免机器状态不同带来的偏差。

## 1. 原有功能：不比 1.7.5 慢

两份十几页的 PDF（968 处差异），各跑 3 轮取中位数：

| | 1.7.5 | 1.8 |
|---|---|---|
| 打开 → 出结果 | 3,369 ms | 3,050 ms |
| 打开期间主线程超过 1 秒无响应 | 0 次 | 0 次 |
| J / K 切换 | 48 / 34 ms | 58 / 32 ms |
| 切到修订审阅 / 回到富文本 | 252 / 129 ms | 225 / 141 ms |
| 滚动 | 56 帧/秒 | 56 帧/秒 |
| 图像模式完成 | 5,763 ms | 5,789 ms |
| 最长的一次卡顿 | 109 ms | 106 ms |
| 结束时渲染进程内存 | 382 MB | 378 MB |

连续操作 3 分钟（J/K、滚动、筛选、切换视图）：

| | 1.7.5 | 1.8 |
|---|---|---|
| 内存峰值（渲染进程） | 920 MB | 879 MB |
| 空闲并回收后 | 684 MB | 668 MB |
| 切换视图 中位 / P95 | 154 / 235 ms | 163 / 241 ms |
| J 中位 / P95 | 38 / 77 ms | 41 / 73 ms |

修订审阅里逐处按 J（约 100 页、556 处差异的 Word）：1.7.5 中位 57–60 ms、P95 79–80 ms；1.8 中位 59–63 ms、P95 83–91 ms。两者差别在测量波动范围内。

结论：没有退步。

## 2. 新功能的预算

| 预算 | 结果 | |
|---|---|---|
| 每个决定写回审阅稿 < 300 ms，界面不卡 | 普通合同（8 处差异）：中位 43 ms。约 100 页、556 处差异：中位 0.30–0.34 秒，波动大（0.2–0.9 秒） | 普通合同达标；极端大文档在这台 2 核测试机上刚好卡在预算边缘 |
| 写回期间主线程无 > 50 ms 的任务 | 0 次（前三个决定时的长任务 1.7.5 也有，是第一次进入审阅状态时的开销） | 达标 |
| 版本识别 < 1 秒 | 放入对方文件后，0.03–0.04 秒出现提示；识别算法本身比对 360 个版本只要 15 ms | 达标 |
| 首页秒开（20 个模板 × 3 版、10 份往来稿 × 10 版） | 1.34 秒（空库 1.21 秒，含应用启动） | 达标 |
| 打开往来稿（约 100 页） | 0.86–0.93 秒 | 达标 |
| 上轮提示和条款历史不拖慢切换 | 往来稿里按 J：中位 61 ms、P95 90 ms，和普通比较一样 | 达标 |
| 生成定稿（约 100 页） | 0.21 秒 | 达标 |

关于写回：

- 写回在后台线程里完成。你连续按 A / R / H 时，界面不会等写回。写回还没完成时又做了新决定，会合并成一次写。
- 大文档慢的原因：每次写回都按全部结论重新生成一份审阅稿，556 处修订都要重新标一遍。这样最稳，不会累积误差。
- 已经做过的优化：同一份对方文件只解压、只预处理一次；拆分 run 改成一次走完；压缩改用最快的级别。
- 在常见的 Apple 芯片 Mac 上应该快 2–3 倍。实测数字以你的复测为准。

## 3. 写回的正确性（零损坏）

| 测试 | 份数 | 结果 |
|---|---|---|
| 固定样本（改词、增删段落、标题列表、表格增删行、超链接、域、制表符、对方原有修订和批注、页眉、文本框、书签、内容控件、分节、移动、拆分合并、空文档、约 100 页） | 11 组 × 7 种决定组合 | 77 / 77 通过 |
| 随机虚构文档（随机样式、表格、列表、超链接、制表符；随机改词、增删、挪段落、改单元格、增删行） | 350 组 × 7 种决定组合 | 2,450 / 2,450 通过 |
| 其中做了 Word 结构校验（OOXML XSD） | 1,477 份 | 全部通过 |
| LibreOffice 打开并转 PDF | 77 份 | 全部成功 |

每份都分别按“接受全部修订”和“拒绝全部修订”，用 pandoc 独立读出正文。读出的文字必须和比较结果推出的预期一字不差。

写不进去的地方不会冒险硬写，审阅稿里保持对方的写法，结论仍保存在 DocDiff 里，状态片上会显示“N 处没写进”。目前包括：

- 页眉、页脚、脚注；
- 文本框；
- 域（自动编号、日期等）；
- 要恢复的图片；
- 被拆分或合并的表格行，以及单元格边界没对齐的行。

```
node scripts/test-review-draft.mjs work/review-fuzz work/review-fuzz-out
node scripts/test-library.mjs && npm test
xvfb-run -a node scripts/e2e-review-draft.cjs huge 15
xvfb-run -a node scripts/e2e-templates.cjs && xvfb-run -a node scripts/e2e-threads.cjs
xvfb-run -a node scripts/perf-library.cjs out.json            # 加 --empty 为空库
APP=<1.7.5 目录> xvfb-run -a node scripts/profile-pdf-compare.cjs A.pdf B.pdf <输出目录>   # 与 1.8 交替运行
```
