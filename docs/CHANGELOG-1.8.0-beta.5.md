# DocDiff 1.8 测试版 5（1.8.0-beta.5）

在 beta.4 的基础上，合并 beta.4 之后的性能与 bug 修复，并处理独立评估（2026-10-30）提出的问题。

## 一、beta.4 之后已提交的修复（本版一起打包）

- 打开往来稿快约 0.1 秒：工具栏收起按钮时不再强制整份文档提前排版。
- 首页删除往来稿、模板后，按 U 可以撤销。
- 删除后的清理计时和撤销提示分开，中途做批量操作不会把清理取消掉。
- 最近比较里属于往来稿的一对，会按往来稿打开。
- “从列表移除”不会删错行。
- 对方原文件被挪走时，提示改为“对方的原文件找不到了”，并给出“选择文件夹…”。

## 二、评估问题逐项

### 1. [P1] 定稿遗漏决定却报告成功：已复现、已修复

- **根因**：写入器对写不进的地方（页眉页脚、文本框、域等）返回“没写进”清单，但生成定稿时丢掉了这个清单，界面直接提示“已生成定稿”。
- **修改**：
  - `client.ts`：生成定稿拆成“生成 → 保存”两步，并算出本该改回原文却没写进的处。这里指拒绝的处，以及选了“改回我方原文”的未决定处。
  - `DraftChip.tsx`：有这样的处时，生成定稿弹窗先停下，列出每一处和原因，主按钮变成红色的“仍然生成定稿”。确认后保存，完成提示写明“有 N 处没能改回原文，定稿里仍是对方的写法”。
- **验证**：
  - `test-final-missed.mjs` 用真实的解析、比较、写入器和 DraftSync，检查输出 DOCX：拒绝页眉金额时报出这一处，文件里确实仍是 198000；接受时不报；未决定的处只在“改回我方原文”时报；正文拒绝能写进，不误报。
  - 界面回归 `e2e-beta5.cjs` F1：beta.4 上失败，beta.5 上通过。
- **限制**：页眉、页脚、脚注里的修改仍然写不进审阅稿和定稿。现在会明确告诉你，不会再报成功。

### 2. [P1] 确认弹窗没有隔离后台快捷键：已复现、已修复

- **根因**：快捷键只认一份“哪些弹窗算打开”的清单，1.8 新加的弹窗没加进去。
- **修改**（`App.tsx`）：改成按界面判断。
  - 任何弹窗开着、或焦点在弹出层里时，A/R/H/J/K/U 都不作用到后台。
  - 已被别处处理的按键（defaultPrevented）也不再处理。
  - 审阅稿首次提示只是说明，不拦快捷键，也不再抢焦点。
- **验证**：
  - beta.4 上，“沿用上轮结论”弹窗打开时按 A，后台接受了一处；beta.5 上不变。
  - `e2e-beta5.cjs` F2：弹窗里依次按 A/R/H/J/K/U，再取消，所有决定和审阅稿文件（修改时间）都没变。

### 3. [P1] 非相邻比较不能恢复，进度和打开的版本对不一致：已复现、已修复

- **根因**：往来稿只记版本，不记“上次比的是哪一对”。打开时总是用最新一版和它的上一版；卡片和版本列表的进度只按“修改后版本”匹配。
- **修改**：
  - `library.ts`、`App.tsx`：往来稿记住上次比较的一对（如 V1 → V3），首页再点它时回到这一对。
  - 卡片显示完整版本对和这一对的进度，如“V1 → V3 · 待审 2 处”。
  - 版本列表的进度按完整版本对匹配。
  - 版本弹出层新增“比较过的”（列出所有比较过的版本对和进度）和“换个比较”（任选两版）。
- **验证**：`e2e-beta5.cjs` F3。
  - 加 V3 时选和 V1 比，审阅一处，回首页：卡片显示“V1 → V3”。
  - 重新打开回到 V1 → V3，进度不变。
  - 弹出层能切回 V1 → V2。
  - beta.4 上失败，beta.5 上通过。

### 4. [P1] 恢复备份后保存失败，会把有效备份也弄坏：已复现、已修复

- **根因**：每次保存先把主文件复制成 .bak，不管主文件是不是坏的。
- **修改**（`electron/persist.cjs`）：
  - 只把确认完好的主文件轮换成备份。这里的“完好”指能解析，或是我们刚写成功、之后没被改过的。
  - 主文件坏了时保留现有 .bak，直到新主文件替换成功。
- **验证**：`test-persist.mjs` 做故障注入，模拟改名前中断，覆盖三种情况。
  - 主文件坏、.bak 好：保存失败后 .bak 仍可读。
  - 主文件好：照常轮换。
  - 主文件写好后被外部弄坏：不会拿它覆盖 .bak。
  - 这组测试在 beta.4 的代码上有 2 项失败，beta.5 全部通过。
- 这个问题要两次故障叠加才会出现，正常保存不受影响。

### 5. [P1] 旧审阅稿任务被替换后仍写盘，却不登记：用确定的时序测试复现、已修复（未在界面上复现）

- **根因**：
  - 生成审阅稿期间切换文档或改比较设置，旧任务被替换，但生成完仍会写盘。
  - 写完后，又因为“已被替换”而不登记路径和修改时间。
- **修改**（`client.ts`）：
  - 生成完、写盘前发现已被替换：不写。
  - 已经提交的写入：一定登记路径和写完后的状态，只是不再通知界面。
  - 同一组比较的新任务会等旧任务写完、登记完再写，所以不会把自己的写入当成“被改过”，也不会多出一份“(2)”。
- **验证**：`test-draft-lifecycle.mjs` 用真实 DraftSync，手动推进 Worker 和写盘，覆盖三种情况。
  - 生成时被替换：不写盘。
  - 写盘时被替换：已登记。
  - 写盘时新任务开始：等待后用登记的状态写入，状态是“已保存”，只有一个文件。
  - 这组测试在 beta.4 的代码上 3 项全部失败，beta.5 全部通过。
- 没有证据表明 beta.4 因此丢过审阅决定。

### 6. [P2] 首页“更多”按 Enter 打开了整行：已复现、已修复

- **根因**：外层整行监听键盘事件，内层“更多”按钮上的 Enter、空格冒泡上来，被当成“打开这一行”。
- **修改**：往来稿、模板、最近比较三种行的键盘处理只响应行本身。
- **验证**：`e2e-beta5.cjs` F5。打开“更多”→ Esc → Enter，或改按空格，都只打开菜单。beta.4 上失败，beta.5 上通过。

### 交付文案统一

- **完成页**：审阅稿已经自动保存时，主按钮是“打开审阅稿”，并写明“所有决定已写进「…」，要发给对方的就是这份”。另有三个次要操作：“在文件夹中显示”“生成定稿…”“导出报告或其他格式…”。没有审阅稿时（如 PDF），仍是“导出审阅结果…”。
- **导出弹窗**：顶部说明要发给对方的审阅稿已自动保存，可直接打开。三种导出改名并写明用途：
  - 重新排版的修订稿 · Word：对方文件不是 Word、或需要统一排版时用。
  - 审阅记录存档 · Word：给自己存档，不发给对方。
  - 比对报告 · PDF：用于内部汇报或留档。
- **四种文件各自的用途**：
  - 审阅稿：发给对方。
  - 定稿：双方都同意后的干净版。
  - 导出的修订稿 / 存档：特殊情况下使用。
  - 报告：内部使用。

## 三、评估中“待验证的风险”

- **外部编辑和写盘之间的竞态：在代码层面复现，已修复。**
  - 复现：beta.4 的写盘逻辑在写临时文件期间如果审阅稿被外部改过，会被覆盖；同一路径的两次写入共用一个临时文件名，两次都报成功。`test-draft-save.mjs` 在 beta.4 的逻辑上有 2 项失败。
  - 修改：新模块 `electron/draft-save.cjs`。同一路径排队写入；临时文件名加随机串；临时文件写完、改名前再核对一次目标文件。
  - 剩余：核对和改名之间仍有一个极短的同步窗口。没有在真实 Word 里测过并发保存。
- **两份相似往来稿的归属：确认存在，已修复。**
  - 以前直接取分数最高的一份。
  - 现在每份往来稿各取最像的一版；最像的两份分数太接近时，提示“这份文件和两份往来稿都很像”，让你选加到哪一份。有单元测试。
- **弹出层重新渲染时抢焦点：确认存在，已修复。**
  - 实际影响：在版本弹出层里给往来稿改名，打一个字输入框就失去焦点，改不了名。
  - 修改：弹出层的监听只在打开、关闭时装卸；焦点已经在弹出层里就不动；审阅稿首次提示不抢焦点；标题不是纯文字的弹出层补了无障碍名称。
  - `e2e-beta5.cjs` 改名一项在 beta.4 上失败，beta.5 上通过。

## 五、需要在 macOS / Windows 上补测（云端是 Linux，没法测）

1. Word 真正打开审阅稿时（`~$` 占用文件），决定先记下、关闭 Word 后自动补写。
2. 在 Word 里改了审阅稿再回到 DocDiff：显示“被改过”，不覆盖。
3. 首页把对方文件拖到版本片 / 弹出层上加入新版本（系统拖放）。
4. 完成页“打开审阅稿”能用 Word 打开（macOS 的默认程序关联 / Windows 的文件关联）。
5. 定稿弹窗列出“没落实”的处后，确认生成，再用 Word 打开定稿核对页眉。
6. Windows：文件名里的中文和“(2)”编号、路径里的反斜杠；同一文件夹下多次生成定稿。
7. VoiceOver / 讲述人：弹出层、确认弹窗的朗读名称。
