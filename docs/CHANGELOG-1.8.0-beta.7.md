# DocDiff 1.8 测试版 7（1.8.0-beta.7）

在 beta.6 的基础上，按试用反馈、资深测试的评估和性能评测修改。界面改动都先在 Figma 里确认过（「方案 · 1.8 beta.7 · 完成页、定稿与最终修订」「方案 · 首页与设置排布」）。

## 审阅稿：手动开始

- 进入修订审阅、做决定，只把结论记在 DocDiff 里，不写任何文件。
- 点工具栏的「生成审阅稿」（或完成页的主按钮），才在对方文件旁边生成一份，并把已经做的决定一次写进去。
  - 生成后弹一次「审阅稿已生成」，写明写进了几个决定。
- 开始之后，这一对文件的每个决定都自动同步；以后再打开同一对，继续同步。
- 往来稿加入新版本、或用模板开始新的一轮，是新的一对文件，要再点一次。
- 没开始审阅稿也能生成定稿：入口在完成页，以及修订审阅检查器的「…」菜单。

## 完成页

- **只有审阅稿真的写好了，才说「要发给对方的就是这份」**（评估 P1-1）。
  - 文件在 Word 里开着、最新的决定没写进去：提示「在 Word 里关掉它，DocDiff 会自动写完」，主按钮是「重新写入」，不再说可以发送。
  - 有几处写不进去：列出是哪几处、为什么，可以直接回到这几处；审阅稿里这几处仍是对方的写法。
- **还没开始审阅稿**：说明「结论目前只记在 DocDiff 里」，主按钮是「生成审阅稿」，点了原地变成写好的样子。
- **有待议时**：副标题写「已看完 N 处修订，M 处待议」；生成定稿降为文字按钮「谈完后：生成定稿…」。
- **生成定稿后回到完成页**，多一条「定稿已生成」，可以直接打开或在文件夹中显示；彩纸只在第一次出现。

## 生成定稿

- 待议和还没决定的处分开说：待议用提示条单独说明（已写成批注、等对方回复，建议谈定后再生成）。
- 没开始审阅稿时，说明文字不再提审阅稿；定稿放在对方文件旁边。

## 问题修复

- **弹窗开着时，菜单栏快捷键不再作用到后台**（评估 P1-2）：
  - 例如「生成定稿」开着时按 ⌘1、⌘N，以前后台会切换模式或清空。
  - 现在和键盘快捷键一样被拦下，只有全屏切换不受影响。
- **离开修订审阅后，不再检查或重建审阅稿**（评估 P2-3）：
  - 窗口切回前台、Word 占用时的轮询都会暂停。
  - 回到修订审阅时检查一次。
- **自动重建的说明写清范围**（评估 P2-4）：设置和提示条都写明「按 DocDiff 里的决定重建，在 Word 里直接改的内容不会保留」。
  - 提示条只在真的写好后出现。
  - 有撤销提示时，新提示叠在它上面，不再被吞掉。
- **「…」菜单**：
  - 最近比较行在窗口下方时，菜单跑到屏幕顶上。现在向上弹时紧贴按钮上方 8px，所有向上弹的浮层一起修好。
  - 菜单样式按组件库：上下各留 8px，两处「…」菜单共用一套，宽 260。
  - 组件库新增 MenuItem。
- **文案**：
  - 导出「审阅记录存档」的提示不再写「定稿」。
  - 设置里的命名规则说明指向新的「审阅稿与定稿」页。

## 首页与设置排布

- **首页 · 老用户**（已有往来稿、模板或最近比较）：
  - 去掉大标题、副标题、模式图标、吉祥物和气泡。
  - 「新比较」放置区从约 280 降到约 88 高（一行写清是哪一边 + 两个按钮，整块照旧能拖放）。
  - 往来稿和最近比较在首屏完整露出。
- **首页 · 第一次用**：
  - 保留标题、副标题和吉祥物，去掉模式图标和气泡。
  - 往来稿和模板还空着时，不放两张空卡片，用一行说明 + 「新建模板」代替。
- **设置**：「审阅」拆成三页，每页一屏放下。
  - 审阅：署名。
  - 审阅稿与定稿：文件名、以前的审阅稿不见了怎么办。
  - 存储：本机保存的数据和清理。
  - 说明文字最多一行，其余放进「ⓘ」悬停。

## 性能

### 纯文本视图按需挂载（性能评测 6）

和富文本视图一样，只挂视口附近的段落，其余用量过的高度占位。

- 选中文字时，两端之间都挂上；全选时整篇挂上，复制的内容完整。
- 同一台机器、同一份虚构文本（约 3000 段），富文本 → 纯文本来回切 12 次：

| | 改前 | 改后 |
|---|---|---|
| 切到纯文本的中位耗时 | 593 ms | 218–255 ms |
| 最长单次卡顿 | 249 ms | 98–99 ms |
| 画布 DOM 节点 | 27,653 | 1,138 |

### 模式切换的内存（性能评测 7）

- 富文本 / 纯文本 / 修订审阅来回切。
  - 约 3000 段文本：60 轮。
  - 约 1700 段 Word：40 轮。
- 每 10 轮强制回收一次后，JS 堆稳定：
  - 文本：39 MB。
  - Word：首轮预热后 44–45 MB。
- 能够回落，没有发现持续增长。这只说明这组测试里没有增长，不据此下「泄漏」或「无泄漏」的结论。

### 已知限制

大审阅稿每次写入约 285 ms。在后台线程里写，不卡界面，这一版不改。
