# DocDiff 1.7.5

本版修复一个严重问题：同时打开两份十几页的 PDF 比较时，界面卡到几乎没法操作。比较结果和 1.7.4 完全一样，只是不再卡。覆盖安装即可，设置和审阅结论原样保留。

## 安装

- **macOS**：打开 `DocDiff-1.7.5-mac-arm64.dmg`（Apple 芯片）或 `DocDiff-1.7.5-mac-x64.dmg`（Intel），把 DocDiff 拖进“应用程序”替换旧版。
- **Windows**：运行 `DocDiff-Setup-1.7.5.exe`，覆盖安装。

## 十几页 PDF 比较不再卡死

- **以前**：两份十几页的 PDF 有几百处差异时，比较一开始窗口就卡住：
  - 富文本把每个汉字都当成单独的元素来画，页面里有 5 万多个元素；
  - 比较本身也在界面线程里算，期间点什么都没反应，也没法取消；
  - 切换视图、滚动、按 J / K 都要等好几百毫秒到两三秒。
- **现在**：
  - 点“开始比较”后立刻出现“正在比较…”和“取消比较”，比较在后台进行。
  - 同一处改动里连续的文字合成一段显示，富文本只画屏幕附近的内容，页面元素从 5 万多降到两千多。
  - 切换富文本 / 纯文本 / 修订审阅都在 0.3 秒内完成，滚动、J / K、筛选都跟手。
  - 图像模式的逐像素比较移到后台，比较过程中界面不卡，内存占用约减半。
- 测试机上（同一份合成文档，968 处差异），修复前后对比：

| | 1.7.4 | 1.7.5 |
|---|---|---|
| 点比较后出现反馈 | 2.3 秒（期间无响应） | 0.2 秒出现进度和取消按钮 |
| 最长一次卡顿 | 1.4 秒 | 0.1 秒 |
| 回到富文本 | 1.9 秒 | 0.1 秒 |
| 滚动 | 24 帧 / 秒 | 41–58 帧 / 秒 |
| 连续操作 3 分钟的内存峰值 | 1,083 MB | 675 MB |

## 其他

- 修订审阅视图分批显示，切过去不再整篇重画几遍。
- 右侧差异清单换筛选时，先显示前 60 条，其余在随后几帧里补齐，内容不变。

## 已知限制

- 两份 PDF 的字号、行距差别很大时，段落可能被切得不一样，会出现成片的“新增 / 删除”。这次只修卡顿，没有改比较方式，后续单独处理。
- 纯文本视图仍一次显示全文。几千段的 Word 文档切到纯文本还要几秒。

详见 `修复说明-1.7.5.md`。
