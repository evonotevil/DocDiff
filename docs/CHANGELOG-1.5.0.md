# DocDiff 1.5.0

## 新功能

**应用内检查更新。** 设置里新增「关于与更新」：显示当前版本、手动检查、更新日志、一键打开下载页，
可以跳过某个版本，也可以彻底关掉自动检查。关掉之后应用不发任何网络请求。
检查只向一个静态 JSON 发普通 GET，不携带文件名、路径或文档内容。

> 这一版**只做发现新版本 + 打开下载页**，不做应用内下载安装。原因是 electron-builder 明确要求
> macOS 应用必须签名才能自动更新，而未签名的 Windows exe 会被企业防火墙和 SmartScreen 拦在下载那一步。
> 证书到位后接 electron-updater 的完整步骤写在 `docs/UPDATE.md`，配置模板在 `build/update-stage1.example.json`。

**算法降级不再是黑箱。** 两份文档差异过大时，段落对齐会退化成按位置粗配（这个保护一直存在，
但以前完全不提示）。现在结果页顶部会说明本次用了简化对齐、以及为什么，可以关掉。

## 性能

| 场景 | 1.4.3 | 1.5.0 |
|---|---|---|
| 纯文本模式首次进入（1200 行） | 34.6 s | 1.7 s |
| 纯文本模式再次进入 | 0.71 s | 0.56 s |
| 大文档比对期间的界面帧率 | 卡死 | p50 16.7 ms（约 60fps） |
| 纯文本 / 修订审阅的差异地图 | 画不出来（0 个刻度） | 完整显示 |
| 切换中英文 | 整篇重新比对 | 不再重新比对 |

具体改了四处：

1. **纯文本 / OCR 视图补上了 token 合并。** 1.4.3 只给富文本视图做了这件事，这两个视图仍然一个
   token 一个 `<span>`，1200 行会生成约 15 万个节点。
2. **差异地图不再对 content-visibility 的行逐个取矩形。** `.code .crow` 和 `.redline > div` 上有
   `content-visibility: auto`，对这类元素调 `getBoundingClientRect()` 会逐行单独触发布局 ——
   实测 516 处差异要 6.5 秒，结果是地图根本画不出来，还把帧拖到 6 秒以上。差异多时改为按行号等距估算。
3. **大文档的比对移到 Worker 里，可以取消。** 判据是体量：实测 1250 段 / 15% 改动的文档 diff 只要
   230 ms，而把结果回传主线程的结构化克隆要 430 ms —— 一律进 Worker 反而更慢。所以小文档继续同步算，
   超过约 15 万字或 3000 段才进 Worker，并显示可取消的进度。
4. **纯文本 / OCR 的结果按当前模式懒算。** 以前不管看不看都要算一遍，等于每次比对做两倍功。

## 修复

- 一段换一段时，即使两段毫不相似也会左右配对，不再拆成"整段删除 + 整段新增"两行。
  整段重写、整段改大小写的场景现在能正常对照着看。
- 未配对的段落按"先删后增"排序（原先这段逻辑的两个分支写得一样，等于没做排序）。
- 中文在 `font-weight: 800` 处会回退到 900，比旁边的英文重一档。补上 Noto Sans SC 的 800 字重后，
  中英文的字重阶梯对齐了（实测墨量 700 → 989、800 → 1079、900 → 1169）。
- 更新检查失败时显示人话（"连不上更新服务器"），不再把 `fetch failed` 甩给用户。

## 工程

- **引擎有回归测试了**：`npm test`，34 个 case，覆盖 LCS、相似度、移动检测、段落拆分合并、
  格式签名、全半角归一、降级标记。写这套测试的过程里直接抓出了上面那两个配对 bug。
- **引擎不再产出本地化文案。** 样式差异改成机器可读的签名（`b+;sz:10>12`），块级差异改成结构化描述，
  翻译挪到 `lib/describe.ts` 在渲染时做。这是"切语言不再重新比对"的根本原因。
