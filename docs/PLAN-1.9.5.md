# 1.9.5 方案（已实施，见 CHANGELOG-1.9.5.md）

## 1. 启动提示“不再提示”：决定数变多时重新提示（2026-11-10 用户认同）

- 现状（1.9.4）：勾了「以后启动时不再提示」后，同一份审阅稿（同一对文件、路径不变）再次登记“待补写”时保留静音（`client.ts` markPending）。之后在这次比较里又做了新决定、又没写进去，也不会再提示。
- 改为：静音时记下当时没写进去的决定数；再次登记时，只有决定数不变（没有新的没写进去的决定）才保持静音；数字变多就当作新情况，重新在启动时提示。换了审阅稿路径照旧重新提示。

## 2. 读取文档里已有的批注（2026-11-10 对齐）

**现状（1.9.4）**：Word 批注只在「文件详情」统计“批注数量”，内容和位置都不读；审阅稿在对方文件副本上写，原有批注原样保留，DocDiff 只追加自己的批注；PDF 注释不读。

**场景**
- A 对方在批注里解释改动、提问、要求确认（可能对应修订，也可能对应没改的文字）。
- B 我方同事在我方稿里留了内部意见；对方改了那段文字时，审阅那处修订要能看到同事的意见。
- C 对方稿里混进了我方内部批注（比如同事直接在对方稿上批过再转给你），生成审阅稿发回去时会带出去。
- D 对方批注没有对应的修订（只有提问），容易漏看。
- E 谈完生成定稿、存档、内部汇报时，批注各自该去哪儿。

**范围（用户选定）**
- 读：修改后文档（对方稿）和原始文档（我方稿）的 Word 批注，含回复和“已解决”状态（`comments.xml`、`commentsExtended.xml`）。往来稿历史轮次的批注、PDF 注释这次不做。
- 呈现：纸面上标出被批注的文字（点开看全文）+ 检查器「批注 N」筛选片列出全部 + 审阅到某处修订时，附近有批注就在审阅栏提一句。
- 我方稿的批注：全部列出；所在文字被对方改过的置顶，审阅那处修订时提醒“同事在这里批过：…”。
- 操作：能回复对方批注，回复在生成审阅稿时作为 Word 里同一条批注下的“回复”写进去；不标“已解决”。我方自己的意见仍可用现在的备注写成新批注。
- 区分我方 / 对方：按作者名，和设置里的审阅人或新增的“我方成员”名单一致的算我方，其他算对方，可手动改。审阅稿里有我方内部批注时，完成页和导出前提醒，可一键不带入。
- 进度：对方批注不计入审阅进度；完成页、生成审阅稿前写“对方有 N 条批注还没回复”，可点进去看，不拦。
- 导出：定稿去掉全部批注（生成前写明去掉几条）；比对报告附批注清单（按条款，双方批注、回复、我方回复，内部批注单独一节）；审阅记录存档保留全部批注。

**待在 Figma 里定的细节**
- 纸面批注标记的样式（不能和四种差异色、需要留意的黄色冲突）；批注锚在被删掉的文字上时怎么显示。
- 检查器里批注和差异的关系：批注单独一组，还是挂在对应差异下面；已解决的默认收起。
- 回复的输入位置（审阅栏 / 批注卡片里）、回复后的状态；“我方成员”名单放在设置的哪一页。
- 内部批注提醒的文案和“不带入”的确认方式。

**技术要点（实施时）**
- 读取：`docx.ts` 解析 `commentRangeStart/End`、`commentReference`，按段落和字符位置挂到块上；`commentsExtended.xml` 的 `paraIdParent` 组成回复线程、`done` 表示已解决。
- 写回复：`draft/ooxml.ts` 在审阅稿里新增批注并在 `commentsExtended.xml` 里指向父批注（Word 2013+ 的回复格式），同时补 `commentsIds.xml`；不带入内部批注时从副本里删掉对应批注和锚点。
- 测试：合成 Word 夹具（双方批注、回复、已解决、批注挂在被删文字上、只有批注没有修订、内部批注混在对方稿里）；用 LibreOffice 打开生成的审阅稿核对回复线程；审阅稿自检脚本补批注检查。
- 隐私：仍然只在本机解析，不上传。

## 补充：没有修订、只有批注的地方（2026-11-10 用户同意）

- 纸面（H1 ③）：没有修订的文字上照常画点线和批注标。我方稿的批注：被批注的文字在修改后文档里原样还在 → 画在那段文字上，卡片注明“批注在我方稿里”；文字被改了 → 挂到对应修订上；整段被删 → 只在检查器里列出，标“已删”。
- 检查器（H2）：「批注」列表最后加一组「没有修订的地方」。
- 审阅栏（H3 ③）：审到最后一处修订时，还有没打开过的这类批注 → 第二行提示“还有 N 条批注不在修订上 · 查看”。仍不计入审阅进度。
