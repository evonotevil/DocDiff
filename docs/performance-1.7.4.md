# DocDiff 1.7.4

本版修复 macOS / Windows 评测里发现的问题：中文 PDF 漏报、差异地图和正文在大文档上卡顿、图像比较的进度说法不准。覆盖安装即可，设置和审阅结论原样保留。

## 安装

- **macOS**：打开 `DocDiff-1.7.4-mac-arm64.dmg`（Apple 芯片）或 `DocDiff-1.7.4-mac-x64.dmg`（Intel），把 DocDiff 拖进“应用程序”，替换旧版。
- **Windows**：运行 `DocDiff-Setup-1.7.4.exe`，覆盖安装。

## 中文 PDF 不再漏掉金额、期限这些行

- **以前**：有些中文 PDF 用的是没有嵌入的中文字体（如“Heiti”“STSong-Light”），解码这类文字要用一组“字符映射表”。安装包里没带这组表，这些行就读不出来，也画不出来。偏偏金额、期限常常就在这些行里，结果显示“全部无差异”。
- **现在**：安装包带上了映射表和标准字体数据。评测用的 30 页原文件，现在能找出 8 处差异，图像模式也能看到第 7、14、21、28 页的改动。
- 如果仍有文字读不出来（比如文件本身损坏），结果页顶部会出现红色警告。警告写清是哪份文档、第几页、有几段没读出，并说明这些内容没有参与比较，“没有差异”不代表这些地方相同。警告里有两个入口：“用其他阅读器打开”原文件核对；文字本身没有编码时，还可以“改用 OCR 文本比较”。
- 图像模式里，这些页不再标“无差异”，改标“可能缺字”。比较范围里也会列出没读出来的页。

## 大文档切换模式、跳转差异不再卡

- **差异地图**：以前每次画图，都要对每一处差异在整篇正文里查找一次。每选中一处差异、每次界面刷新，还会再整张重画。现在先一次性建好“差异 → 位置”的索引；差异很多时，只量每一行的位置；只有版面尺寸真的变了才重画；切回同一个模式时，直接沿用上次的结果。
- **富文本正文**：以前整篇一次挂到页面上（3000 段约 3 万个元素），切回富文本时整篇重建。现在只挂视口上下一两屏的段落，其他部分先用同样高度的占位代替，滚到哪里挂到哪里。没在屏幕上的段落，选中别的差异时也不再重新渲染。
- 以下操作都照常可用：跳转到差异、点差异地图、拖动滚动、跨段选字、全选复制、点词对齐两侧、只看有变化的段落、修订审阅。选字时，选区经过的段落会全部挂上，不会漏字。全选时会挂上全文。
- 3000 段的 Word（1712 处差异），同一台测试机、各跑 3 次取中位数：

| | 1.7.3 | 1.7.4 |
|---|---|---|
| 从纯文本切回富文本 | 3.3 秒 | 0.16 秒 |
| 切回时最长的一次卡顿 | 1.16 秒 | 无（没有超过 50 毫秒的） |
| 连按 5 次“下一处”期间最长卡顿 | 0.62 秒 | 无 |
| 页面元素数 | 29,887 | 3,996 |
| 稳定后 JS 堆 | 148 MB | 83 MB |

在 Apple M2 上，同一个文档：切回富文本从 0.66 秒降到 0.10 秒，连按“下一处”期间的卡顿从 0.17 秒降到 0。mac 评测里切换超时的 3000 段全文改写文档，1.7.3 切回富文本时约 45 秒无响应，1.7.4 切换都在几秒内完成。

## 图像 / OCR：“选了哪些页”和“比完了几页”分开说

- **以前**：只要选的是全部页面，比较一开始就显示“比较了全部 30 页”，其实才比了 8 页。
- **现在**：
  - 进行中：“比较范围：全部 30 页；已完成 8/30 页”。
  - 全部比完：“全部 30 页已比较”。
  - 只比一段时：“只比较了第 a–b 页，共 n 页；其余页面没有比较”。
  - 新增“停止比较”。停止后显示“已停止：……已完成 9/30 页，还有 21 页没有比较”，已经比好的页保留，点“继续比较”从下一页接着比。
  - 某一页出错时：写清已完成几页、还有几页没比较，可以“重试”。
  - OCR：开始前只说范围；识别中显示“已识别 x/6 页（两份文档合计）”；取消后写明“没有生成比较结果”。
- 英文界面同步。

## 其他修复

- 图像比较做到一半切走，已经生成的页面图片现在会释放。1.7.3 会一直留在内存里。
- “新建比较”时清掉上一组的页面缓存。Word / TXT 排版出来的 PDF 只留最近 4 份。
- 新建比较后，侧栏不再显示上一组文档的差异数（比如扫描件旁边显示“纯文本 1712”）。进入图像模式时，也不会先闪出上一组的结果。
